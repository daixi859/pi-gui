# 0017 PiDS：并行于宿主规范的独立设计系统

> **已废弃（2026-11-13）。** `agent-design/src/ds/` 已整体删除：这个包收缩成「对话块组件库 + 回放验收场」两件事（ADR-0018）。本记录保留作当时的决策依据——PiDS 的令牌分层与对比度门槛仍是好参考，但项目现在只有一套样式规范（宿主 `--dsw-*`，见 `docs/STYLE.md`），对话块的令牌在 `.pi-blocks` 作用域内自持。

## 背景

`agent-design` 原本只是一套「把 pi 事件流还原成对话块」的复刻页：样式全部从宿主搬来（`--dsw-*` 令牌、`--app-*` 补丁、`app.css` 里 1477 行全局裸类），只为让块看起来和宿主一致。

现在它要承担另一件事：给 pi agent 设计**自己的**界面。沿用宿主的令牌会立刻撞上冲突——宿主规范里次要与最弱文字只有 3.36:1 / 1.99:1 对比度，间距刻度是 2/4/8/16，字号只有 12/14 两档。它是为「和 harness 对齐」服务的，不是为「长时间阅读」服务的。照着它设计，等于把宿主的妥协复制一遍。

同时有硬约束：`design-platform.css` 的 404 个 `--dsw-*` 被 `app.css` 129 处、3 个 CSS Module 16 处、`FileTypeIcon.tsx` 162/165 行硬引用，删不掉也替换不掉；`--dsw-*` 声明在 `body` 上（`design-platform.css:4`），会吃掉任何同名 `:root` 变量。旧 Player / Gallery 两页也是既有验收脚本（`scripts/shoot.mjs`）的对照物，不能删。

## 决策

1. **新系统与宿主规范并行，不继承、不替换。** 判据：能论证的通用规则（对比度、焦点可见、间距节奏、状态矩阵、键盘路径）一律遵守；「宿主一直这么做」的取值（刻度、字号档、muted 色）一律丢掉；pi 的产品事实（回合/分组/tool 三类结构、会话列表）保留。
2. **落点 `agent-design/src/ds/`，令牌前缀 `--pi-*`，声明在 `.pi-root` 上。** 前缀与既有 `--dsw-*` / `--ds-*` / `--app-*` 三套零冲突；声明在更内层的 `.pi-root` 而不是 `:root`，才能盖过 `body` 上的同名层级问题。深色在 `.pi-root[data-pi-theme='dark']` 重绑同名语义令牌，组件只认语义名。
3. **令牌三层：primitive → semantic → component。** primitive 是 OKLCH 色阶与刻度（`--pi-n-*`、`--pi-a-*`、`--pi-fs-*`、`--pi-sp-*`、`--pi-r-*`、布局宽度）；semantic 是用途（`--pi-canvas`、`--pi-fg-2`、`--pi-edge`、`--pi-accent`）；component 是控件几何（`--pi-control-h-md`、`--pi-switch-w`、`--pi-ring`）。组件 CSS 只许用后两层，出现 primitive 名即视为越层。当前两套主题各 145 个令牌，令牌 JSON 由规范页运行时导出。
4. **样式用 CSS Modules，不用 Tailwind。** 宿主用 Tailwind 是因为它已经在用；这里从零开始，CSS Modules 的局部作用域 + 原生 `@media`/`@keyframes` 更直接，也不需要为「刻度外的值」造任意值语法。
5. **字号 11/12/13/14/16/20/24/28，间距 2/4/8/12/16/20/24/32/40/48（4px 基准，2 只做光学微调），圆角 4/8/12/16/999。** 11 档只给等宽微标签（令牌名、色值、代码语言标、差异计数），不排正文。行高按用途分：控件 1.5、界面 1.6、长文 1.75——中文是方块字，1.5 行高在密集段落里会挤。
6. **WCAG AA 是硬门槛，不是参考线。** 正文与次要文字 ≥ 4.5:1，边框与图标 ≥ 3:1，禁区颜色在规范页直接标出。对比度由 `agent-design/src/ds/lib/color.ts` 在运行时从计算样式算出（OKLCH 解析 + 合成 + 相对亮度），不是手填常量——手填的值会随令牌改动过期。
7. **浮层用 `PiRoot` 自带的传送门宿主，不用 `document.body`。** 令牌只在 `.pi-root` 作用域内，`createPortal(..., document.body)` 会让菜单、弹窗、Toast 全部掉到令牌作用域外，背景与描边一起失效。`PiRoot` 内部渲染一个 `div.pi-portal`（`display: contents`，不生成盒子），`PiPortal` 传进去。
8. **外壳三区：规范 / 基础组件 / 高保真；旧 Player、Gallery 移到顶栏最右，且不包进 `PiRoot`。** 旧页是「新规范之前的版本」这一论断的对照物，被 `.pi-root` 改掉字体与底色就不再是对照物。
9. **验收脚本独立：`agent-design/scripts/shoot-ds.mjs`。** 断言默认浅色、规范页首屏不被 autoFocus 抢滚动、扫光真的在动、令牌导出 JSON 两套主题各 ≥100 项且取值不同、组件页 26 个条目、命令面板 Esc 后遮罩归零、每步无横向溢出。旧 `shoot.mjs` 只改了三处条件断言（详见该文件注释），继续守旧页。

## 否掉的方案

- **把宿主令牌「升级」成 PiDS 的值**：`--dsw-*` 被 150+ 处硬引用，改值会让宿主与复刻页一起改变，且无法只对 `agent-design` 生效（同一份 CSS 两个消费方）。
- **PiDS 令牌写在 `:root`**：会和 `body` 上的 `--dsw-*` 打层级官司；且规范页要在同一屏并排浅色/深色两个样例，令牌必须能被一个元素整体切换。
- **旧对话块套新令牌（映射层）**：旧块的结构是为宿主尺寸调的，套上新刻度会得到「两边都不像」的中间态；重画六块反而更省。
- **Tailwind + 设计令牌类**：与宿主的 `bg-panel` 体系同形，读代码时无法区分「哪套系统的令牌」，迁移时也难判断。
- **引入 webfont 统一字形**：多一次网络请求，且中文 webfont 体积不可接受；改用按平台最优的原生 UI 字栈，等宽栈显式排掉裸 `monospace` 尾部（Windows 中文会回退 SimSun 出方框）。

## 后果

- `agent-design` 现在有两套并存的样式系统。写新代码放 `src/ds/`，写旧页修复仍用旧类；两者靠 `.pi-root` 边界隔离，跨界的只有 `App.tsx` 的一处三元。
- 字号多了 11、13 两档，和宿主刻度（12/14）对不上。这是有意的：宿主刻度是「只留两档」的简化，PiDS 需要 13 做界面主力、11 做等宽微标签。
- 对比度改令牌后必须看规范页——那里是运行时算的，会自动飘红。
- 令牌导出（`src/ds/spec/useTokenExport.ts`）遍历全部样式表收集 `--pi-` 名，再在临时 `.pi-root` 元素上读值。新增令牌无需登记，但**令牌名必须带 `--pi-` 前缀**，否则不会被导出也不会被规范页展示。
- 旧 `shoot.mjs` 里 `.runningTail` 与部分夹具的 `.changes` 断言已改成条件式：前者在 HEAD 源码里就不存在，后者本来就随夹具不同为 0。
